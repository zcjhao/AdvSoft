## 5. Files

`POST /api/files` takes `multipart/form-data` with one part named `file`. The size limit is
10 MiB = 10485760 bytes. If you use aiohttp, its default request limit is 1 MiB: create the
app with `web.Application(client_max_size=11 * 1024 * 1024)` and check the size yourself: read the
`file` part with `await part.read_chunk()` in a loop, add up the bytes, and answer `413` as soon as
the total passes 10485760 (never let an exception turn it into a `500`).

5.1 **Upload.** A 13-byte `hello.txt` sent as `text/plain` returns
    `201 {file: {id, uploader_id, filename: "hello.txt", content_type: "text/plain",
    size: 13, created_at}}` with `uploader_id` the caller. A 2 MiB file → `201` with
    `size: 2097152`.

5.2 **Metadata.** `GET /api/files/{id}` (any node) → `200 {file}` with the same object.
    Unknown id → `404`. No token → `401` (also on upload and download).

5.3 **Download.** `GET /api/files/{id}/download` (any node) returns `200` with exactly the
    uploaded bytes (binary files too, for example a PNG), a `Content-Type` header equal to
    the uploaded `content_type`, and a `Content-Disposition` header carrying the filename,
    for example `attachment; filename="hello.txt"`.

5.4 **Too big.** A file of 10485761 bytes → `413`.

5.5 **No file part.** A multipart body without a `file` part → `400`.

5.6 **Attach.** `POST /api/channels/{id}/messages` `{"body": "see file", "file_ids": [<id>]}`
    by the uploader → `201`, and `message.files` is `[<FileObj>]` (also in the listing).

5.7 **Attach rules.** Attaching a file uploaded by someone else, a file already attached to
    another message, or an unknown file id → `400`, and no message is created.

## 6. Slash commands

A message `body` that starts with `/` is a command. Commands run in the channel of the
`POST /api/channels/{id}/messages` call, and the caller must be allowed to post there.

| Body | Result |
|---|---|
| `/me <text>` | `201 {message}`, a normal message whose `body` is exactly `"/me <text>"` (not stripped) |
| `/shrug <text>` | `201 {message}` whose `body` is `"<text> ¯\_(ツ)_/¯"`; plain `/shrug` gives just `"¯\_(ツ)_/¯"` |
| `/topic <text>` | `201 {"message": null, "channel": <ChannelObj with topic <text>>}`, appends `channel.updated` |
| `/invite @<username>` | `201 {"message": null, "invited_user": <UserObj>}`; that user becomes a member of the channel (and of the workspace, as `member`, if needed), appends `member.joined` |
| `/archive` | `201 {"message": null, "channel": <ChannelObj, is_archived: true>}`, appends `channel.archived` |
| `/unarchive` | `201 {"message": null, "channel": <ChannelObj, is_archived: false>}`, appends `channel.unarchived` |
| `//<text>` | not a command: a normal message whose `body` is exactly what was sent, for example `"//literal"` |

The shrug is the 9-character string `¯\_(ツ)_/¯` with one backslash (written `"¯\\_(ツ)_/¯"`
inside JSON).

6.1 **/me.** `"/me waves"` → `201` with `body` `"/me waves"`.

6.2 **/shrug.** `"/shrug hello"` → body `"hello ¯\_(ツ)_/¯"`; `"/shrug"` → body `"¯\_(ツ)_/¯"`.

6.3 **Literal.** `"//literal"` → `201` with body `"//literal"`.

6.4 **Bad commands.** An unknown command (`"/frobnicate now"`) → `400`. `"/me"` with no text
    (or only spaces) → `400`. No message is created.

6.5 **/topic.** `"/topic Launch day"` → `201` with `message: null` and `channel.topic`
    `"Launch day"`; the workspace detail shows the new topic.

6.6 **/invite.** `"/invite @carol"` → `201` with `message: null` and `invited_user.id`
    carol's id; carol is now in `GET /api/channels/{id}/members` and can post there.
    Unknown username → `404`.

6.7 **/archive and /unarchive.** `"/archive"` from the workspace owner → `201`,
    `channel.is_archived: true`; then a normal post → `423`. `"/unarchive"` is still allowed
    in the archived channel → `201`, `channel.is_archived: false`, and posting works again.
    Both are workspace-owner only: from a plain member → `403`.

Every request must answer within 5 seconds.
