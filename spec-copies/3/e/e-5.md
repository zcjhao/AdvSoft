## Adds (JavaScript functions inside `index.html`)

| Function | What it does |
|---|---|
| `api(method, path, body)` | `fetch` with `Authorization: Bearer <token>`; returns `{status, data}` |

## 6. Behaviour

**Auth.** `auth-form` has a `data-mode` attribute, `"login"` or `"register"`, and the inputs
`name="username"` and `name="password"` (in register mode also an optional
`name="display_name"`). Clicking `auth-toggle` switches the mode. Submitting calls
`POST /api/auth/register` or `POST /api/auth/login`. On failure (any non-2xx) it shows the
reason as visible, non-empty text in `auth-error` and stores nothing. On success it stores
the token in `localStorage["huddle.token"]`, hides the auth form, shows the app and puts the
user's username in `current-user`. Register logs in directly (no second form).

**Workspace.** A signed-in user with no workspace sees `empty-state-create-workspace` holding
`workspace-create-form` (inputs `name="slug"` and `name="name"`, and a button with the
attribute written out, `<button type="submit">`; the check clicks `[type="submit"]`)
and `join-workspace-form` (input `name="code"`, accepting an invitation code). Creating
shows the new workspace. The app shows the first workspace of `GET /api/workspaces`:
`workspace-header` contains its `name`.

**Channels.** `channel-list` (inside `sidebar`) holds one `channel-entry` per channel the
user is in, each the clickable element with `data-channel-id="<id>"` and
`data-channel-name="<name>"`, showing `# <name>`. Clicking one selects it: `channel-title`
shows the name (`# <name>` is fine) and `channel-topic` shows its topic. After sign-in the
app selects `#general`. `new-channel-btn` opens `create-channel-modal`; `create-channel-form`
has input `name="name"`, the `create-channel-private` checkbox, `create-channel-submit` and
`create-channel-cancel`. A successful create closes the modal, adds the entry and selects
the new channel. A failure (for example `409` for a duplicate name) keeps the modal open
and shows visible, non-empty text in `create-channel-error`.

**Empty channel.** A channel with no messages shows, inside `message-list`, an element with
`data-testid="empty-channel"` and visible text such as `No messages yet. Say hello!`.

**Logout.** `logout-btn` removes the token from `localStorage` and shows `auth-form`. Logging
in again with the same credentials shows the same workspace.

6.1 **Sign-up error.** In register mode, submitting username `bad name` and password `short`
    shows a visible, non-empty `auth-error` and stores no token.

6.2 **Sign-up.** In register mode, a valid new username and password signs the user in:
    `localStorage["huddle.token"]` holds a token of 16+ characters and `current-user`
    shows the username.

6.3 **Create a workspace.** The new user sees `workspace-create-form`, fills `slug` and
    `name` and submits; `workspace-header` shows the name, and `channel-list` holds a
    `channel-entry` with `data-channel-name="general"` whose text contains `#`.

6.4 **Create a channel.** `new-channel-btn`, then name `ui-room`, then
    `create-channel-submit`: the modal closes, an entry `ui-room` appears, and
    `channel-title` shows `ui-room`.

6.5 **Empty state.** The new channel `ui-room` shows a visible `empty-channel` with
    non-empty text.

6.6 **Duplicate name.** Creating `ui-room` again keeps the modal open with visible,
    non-empty `create-channel-error`, and there is still one `ui-room` entry.

6.7 **Switching.** Clicking the `general` entry makes `channel-title` show `general`;
    clicking `ui-room` makes it show `ui-room`. A topic set with
    `PATCH /api/channels/{id}` shows in `channel-topic` after selecting the channel again.

6.8 **Logout and login.** `logout-btn` shows `auth-form` and clears `huddle.token`; logging
    in (login mode) with the same credentials shows the same `workspace-header` and the
    `general` entry.

Every request must answer within 5 seconds.
