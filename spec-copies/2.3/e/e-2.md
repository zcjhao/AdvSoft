## 3. Protocol

Lines end with `\r\n`. The server name in prefixes is `huddle`. A user's nick is free text
chosen with `NICK`, unique among connected IRC clients. A user's IRC prefix is
`<nick>!<username>@huddle`.

| Client sends | Server answers |
|---|---|
| `PASS <token>` | nothing yet; must come before `NICK`/`USER`; the token is a normal API bearer token |
| `NICK <nick>` + `USER <u> 0 * :<real>` (either order) | once both arrived and the token is valid: `001` (`:huddle 001 <nick> :Welcome ...`), `002`, `003`, `004`, `005`, then `422 <nick> :MOTD File is missing` |
| bad or missing `PASS` when registering | `:huddle 464 * :Password incorrect`, then close the connection |
| `NICK <nick>` already used by another connection | `:huddle 433 * <nick> :Nickname is already in use`; keep the connection open so the client can send another `NICK` |
| `JOIN #ws/chan` (a channel the user may join) | `:<prefix> JOIN #ws/chan`, then `331` or `332` (topic), `353 <nick> = #ws/chan :<nicks or usernames of members>` (must include the joiner's nick), `366 <nick> #ws/chan :End of /NAMES list`; joining a public channel makes the user a member like `POST /api/channels/{id}/join` |
| `JOIN` of anything else (`#ws-chan`, an unknown or a private channel the user is not in) | `403 <nick> <name> :No such channel` |
| `PING <token>` | `PONG huddle <token>` (or `:huddle PONG huddle :<token>`) |
| `PONG`, `NAMES`, `WHO`, `LIST`, `TOPIC`, `MODE` | accepted: a sensible reply or nothing, never `421` |
| `QUIT [:msg]` | close the connection; send no error reply |
| any other command | `421 <nick> <COMMAND> :Unknown command` |

Before registration completes only `PASS`, `NICK`, `USER`, `PING` and `QUIT` are processed.

3.1 **Register.** `PASS <token>`, `NICK`, `USER` → `001`, `002`, `003`, `004`, `005` in this
    order, then `422`. The `001` line carries the nick.

3.2 **Bad password.** `PASS not-a-token` then `NICK`/`USER` → `464`.

3.3 **Nick in use.** A second connection asking for a nick that a connected client already
    uses gets `433` and stays open: it can then send another `NICK` and complete
    registration (`001` … `422`).

3.4 **Ping.** `PING abc123` → a `PONG` line carrying `abc123`.

3.5 **Join.** `JOIN #<slug>/general` → the `JOIN` line with the user's prefix, then `353`
    listing the nick, then `366`, in that order.

3.6 **Unknown channels.** `JOIN #<slug>-general` and `JOIN #<slug>/no-such-channel` → `403`
    each.

3.7 **Unknown command.** `FOOBAR` → `421`, and the connection still answers `PING`.

3.8 **Accepted commands.** `NAMES #<slug>/general`, `WHO #<slug>/general`, `LIST`,
    `TOPIC #<slug>/general`, `MODE #<slug>/general` and `PONG huddle` produce no `421`, and
    the connection stays open.

3.9 **Quit.** `QUIT :bye` → the server closes the connection within 2 seconds without
    sending a `4xx` numeric.

Every reply must arrive within 3 seconds.
