# E.4: the web UI shell (served HTML, pinned hooks, button colours)

Spec 4 of 6 for Component E (IRC gateway, web UI and message edits). Sections: 5 (rule
numbers match the check output). Check: `bash /spec/e/checks/check_e_4.sh` (it drives a
headless Chromium with Playwright from `/opt/test-venv`, already installed; you install
nothing for it).

Do not start this spec until `check_e_3.sh` prints `RESULT: ... 0 failed`.

## Uses

| Function | Used here for |
|---|---|
| every HTTP route built so far | The UI calls them with `fetch` and the bearer token |

## Adds

| Function | What it does |
|---|---|
| `GET /` (and `GET /static/...` if you split files) | Serves `/app/static/index.html` from every node, `Content-Type: text/html` |
| `/app/static/index.html` | One single-page app: plain HTML, CSS and vanilla JavaScript in one file, no build step, no CDN |

The UI is graded by an automated browser at 1280x900 and by Playwright through the hooks
below. Write the whole skeleton (every pinned element) as static markup in `index.html`, and
let JavaScript only show/hide it and fill in data. Hidden elements stay in the DOM (use
`hidden` or `display: none`).

### Button roles and colours

Every button below carries `data-button-role="<role>"` in the served HTML and, at rest (not
hovered, focused or disabled), exactly this computed `background-color` and `color`. Use a
plain `background-color` (no gradient, image or transparency), for example
`[data-button-role="primary"] { background-color: #007a5a; color: #ffffff; }`.

| Role | Background | Text | Buttons (`data-testid`) |
|---|---|---|---|
| `primary` | `#007a5a` = `rgb(0, 122, 90)` | `#ffffff` | `auth-submit`, `send-btn`, `thread-send`, `create-channel-submit`, `join-workspace-submit`, `workspace-general-submit`, `create-invitation-submit`, `channel-topic-submit`, `channel-add-member-submit` |
| `danger` | `#e01e5a` = `rgb(224, 30, 90)` | `#ffffff` | `archive-channel-btn`, `logout-btn` |
| `secondary` | `#1264a3` = `rgb(18, 100, 163)` | `#ffffff` | `new-channel-btn`, `create-invitation-btn`, `unarchive-channel-btn`, `create-channel-cancel`, `close-thread`, `channel-settings-close`, `workspace-settings-close`, `channel-settings-btn`, `workspace-settings-btn` |

### Rules

5.1 **Served.** `GET /` on `8000`, `8001` and `8002` → `200` with `Content-Type: text/html`
    and the same page.

5.2 **Pinned test ids.** Every `data-testid` of the first list above is in the served HTML.

5.3 **Pinned DOM ids.** All five DOM ids are in the served HTML.

5.4 **Button roles.** Every button in the table has the right `data-button-role` in the
    served HTML.

5.5 **Button colours.** In Chromium at 1280x900, every button in the table has exactly its
    role's computed `background-color` and `color` (the check reads them with
    `getComputedStyle`, also for buttons inside hidden modals).

5.6 **Signed out.** With no token in `localStorage`, the page shows `auth-form` (visible),
    and `message-list` is not visible.

Every request must answer within 5 seconds.
