# E.3: bridging IRC and the web

Spec 3 of 6 for Component E (IRC gateway, web UI and message edits). Sections: 4 (rule
numbers match the check output). Check: `bash /spec/e/checks/check_e_3.sh`.

Do not start this spec until `check_e_2.sh` prints `RESULT: ... 0 failed`.

## Uses

Call these functions from earlier E specs. Do not write a second version of any of them.

| Function | Used here for |
|---|---|
| `post_message(user, channel, body)` | `PRIVMSG` from IRC writes through it, so the message gets the next dense `event_id` like a web post |
| `irc_channel(name)` | `PRIVMSG` targets |
| events table | The gateway polls it every 50 ms like an HTTP node's `event_pump` |

## Adds

| Function | What it does |
|---|---|
| `irc_event_pump()` | In the gateway process: read new events from the shared table every 50 ms; for each `message.created` in a channel, send `:<author-username>!<author-username>@huddle PRIVMSG #ws/chan :<body>` to every IRC client joined to it, except the client that sent it over IRC |

The gateway is its own process and reads and writes only the shared store, so it keeps
working when any HTTP node dies, and HTTP nodes keep working when it dies.

## 4. Bridging

4.1 **IRC to web.** An IRC client (alice, joined to `#<slug>/general`) sends
    `PRIVMSG #<slug>/general :hello from irc`. Within 2 seconds the message is in
    `GET /api/channels/{id}/messages` (on any node) with that `body` and `author_id`
    alice's id.

4.2 **IRC to WebSocket.** A socket subscribed to that channel gets it as `message.created`
    with `event_id` = head + 1.

4.3 **Web to IRC.** Bob posts `"hello from web"` over HTTP; within 2 seconds alice's IRC
    connection receives `:<bob's username>!<bob's username>@huddle PRIVMSG
    #<slug>/general :hello from web` (the check matches the `:<bob's username>!` start and
    the `PRIVMSG #<slug>/general :hello from web` end).

4.4 **IRC to IRC.** A second IRC client (bob, joined) receives alice's `PRIVMSG` as
    `:<alice's nick or username>!... PRIVMSG #<slug>/general :<body>`.

4.5 **Mixed writers stay dense.** Three IRC messages and three web posts, alternating, give a
    subscriber six `message.created` events with consecutive `event_id`s, in the order sent.

4.6 **A killed HTTP node.** After the check kills the process that owns port `8001`
    (`SIGKILL`), a message posted on `8000` still reaches the IRC client, and an IRC
    `PRIVMSG` still shows up in the listing on `8002`. (`start.sh` brings `8001` back; the
    check waits up to 15 seconds for it before it ends.)

Every reply must arrive within 3 seconds.
