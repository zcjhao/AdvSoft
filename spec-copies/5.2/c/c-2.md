## 3. Direct messages

3.1 **Open a DM.** `POST /api/dms` `{"user_id": <bob's id>}` from alice returns
    `200 {"channel_id": <id>}` (`200`, not `201`, even the first time).

3.2 **Same channel.** Calling it again returns the same `channel_id`, and bob calling it with
    alice's id also returns the same `channel_id`. A different pair (alice and carol) gets a
    different channel.

3.3 **Use the DM.** Both participants can post (`201`) and list (`200`) messages with the
    normal message routes, and a subscriber on another node gets `message.created` for it. A
    third user gets `403` on posting and on listing.

3.4 **Errors.** No token → `401`. Unknown `user_id` → `404`. Missing `user_id` → `400`.

## 4. Profiles

The profile fields are `display_name`, `timezone`, `avatar_url`, `status_text`,
`status_emoji` (all strings). `id` and `username` never change.

4.1 **Get a user.** `GET /api/users/{id}` (any node) returns `200 {user}` with every
    `UserObj` field. Defaults: `display_name` as sent at register (else the username),
    `timezone: "UTC"`, `avatar_url`, `status_text`, `status_emoji` all `""`.

4.2 **Unknown or no token.** Unknown id → `404`. No token → `401`.

4.3 **Update.** `PATCH /api/users/me` with any subset of the profile fields returns
    `200 {user}` with the new values; fields not sent keep their old values. The change is
    visible right away in `GET /api/users/{id}` and `GET /api/auth/me` on the other nodes,
    and in the `author` of messages listed afterwards.

4.4 **Timezone.** `timezone` must be an IANA name that Python's
    `zoneinfo.ZoneInfo(name)` accepts, for example `"America/New_York"`. An unknown one
    (`"Mars/Phobos"`) or an empty string → `400`, and nothing is changed.

4.5 **Lengths.** `display_name` 1 to 80 characters, `status_text` 0 to 140,
    `status_emoji` 0 to 64, `avatar_url` 0 to 1024. Anything outside (for example an empty
    or 81-character `display_name`, a 141-character `status_text`) or a value that is not a
    string → `400`, and nothing is changed (not even the valid fields in the same request).

4.6 **Broadcast.** After a successful `PATCH /api/users/me`, every open WebSocket on every
    node (subscribed to any channel or not) receives within 2 seconds
    `{"type": "user.updated", "user": <UserObj with the new values>}`. This frame has no
    `channel_id` and no `event_id`, and it does not touch any channel's event sequence.

Every request must answer within 5 seconds.
